## DVC pipeline
- use local disk to store data of different versions
- Intialized dvc, use windows+r type **%temp%**
```sh
dvc init
dvc remote add -d myremote C:\Users\email\AppData\Local\Temp\dvc
```
- add py files from **end-to-end-mlops** and create dvc.yaml file
```sh
dvc stage add --force -n data_collection `
  -d src/data/data_collection.py `
  -o data/raw `
  --params data_collection.test_size `
  python -m src.data.data_collection
# check dvc.yaml file and data/raw
dvc repro # check dvc.lock
dvc dag

dvc stage add --force -n data_process `
  -d src/data/data_processing.py `
  -d data/raw `
  -o data/processed `
  python -m src.data.data_processing


# check dvc.yaml file and data/processed
dvc repro # check dvc.lock
dvc dag

dvc stage add --force -n model_build `
  -d src/model/model_building.py `
  -d src/data/data_collection.py `
  -d data/processed `
  -o models/model.pkl `
  --params model_building.n_estimators `
  python -m src.model.model_building
# check dvc.yaml file and model.pkl
dvc repro # check dvc.lock
dvc dag
```
- Change model_evaluation.py and include dagshub to track the model
```sh
dvc stage add --force -n model_eval `
  -d src/model/model_evaluation.py `
  -d models/model.pkl `
  --metrics reports/metrics.json `
  -o reports/run_info.json `
  python src/model/model_evaluation.py
# check dvc.yaml file and metrics.json
dvc repro # check dvc.lock
dvc dag
dvc metrics show
```
- Change model_registration.py
```sh
dvc stage add --force -n model_registration `
  -d reports/metrics.json `
  -d src/model/model_registry.py `
  python src/model/model_registry.py staging
```
- once the above is done it will deploy **DCV-pipline** Experiment in the mlflow and dsagshub.
